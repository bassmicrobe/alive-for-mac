# パフォーマンス・UI/UX 再監査 — 2026-10-15

## 対象

- `bassmicrobe/alive-for-mac`、監査開始時 `main` / `1d55643`、ソース版 `0.3.0`。
- macOS 27.0.1、Apple Silicon、Swift 6.4。0.2.1 の監査後に追加された差分スキャン、状態判定、Mac 連携と、その周辺 UI を重点確認。
- 監査開始時の作業ツリーはクリーン。既存の `/Applications/Alive for Mac.app` は 0.2.1。今回の検証には別 ID のアプリと専用 `ALIVE_HOME` を使用した。
- 今回の変更は未リリース。`VERSION` は変更せず、日英 README に未リリースの変更点を記録した。

## 修正内容

| 問題と影響 | 修正 | 検証 |
|---|---|---|
| 通常起動時に `CatalogWatcher` が開始されず、セットを保存・追加しても自動更新されない | `CatalogModel.start()` から監視を一度だけ開始。初期読込み中の変更は既存の再試行で処理 | 実画面で再現。通常起動から実 FSEvents による保存後の更新まで回帰テストを追加 |
| 起動時の FSEvents 履歴が大量の場合、保持するイベント数と差分領域の整理処理が膨張する | イベント保持を16,384件、領域整理を400件基準に制限。上限超過・履歴欠落は安全な全件スキャンへ移行 | バッファ上限、履歴終了マーカー、履歴欠落のテスト |
| 古いスキャンが履歴待ちを続け、新しい操作への反応が遅れる | 履歴再生にもキャンセルを伝達し、待機中は20ms刻みで確認。キャンセル後に残りのルートへ進まない | キャンセル待機、未処理ルート・チェックポイントの保護を検証 |
| ルート自体が読めても、その下の一部フォルダが読めない場合、読み取れた分だけで一覧を上書きし得る | プロジェクトは前回の一覧・キャッシュ・履歴位置を保持。サンプルも不完全なルート走査では以前のツリーを保持 | 読取り失敗と復旧、キャッシュ不変のテスト |
| 大きなサンプルフォルダでキャンセル確認が遅れる | 同一フォルダ内でも256項目ごとに確認 | 横に広いディレクトリの途中停止を検証 |
| スキャン中に届いた新しいドライブ状態を、古い取得結果で戻す可能性 | マウント状態の世代を比較し、新しい通知を保持 | スキャン途中にマウント状態が変化する回帰テスト |
| Spotlight 更新が重複すると、不要になった大量の登録処理を最後まで続ける | 以前の更新をキャンセルし、各バッチ間で停止。成功済みバッチだけをチェックポイントに保存して次回再開 | 450件のうち最初の200件後に停止し、残り250件のみ再開するテスト |
| Widget の古いスナップショットが遅れて保存され、最新の内容を上書きし得る | アプリ単位の publisher で書込みを直列化し、古い作成処理は保存前に停止 | 古い作成処理を意図的に遅らせ、最終ファイルが最新になることを検証 |
| Quick Look の画像高さ制限により、多数のトラックの下側が欠ける | 最大1500×1100pxの既定画像内へ全体を縮小。高さだけを切り詰めない | 69・128・400トラックの最終クリップを画素で確認。400トラックの生成画像も目視確認 |
| 切断中のフォルダの Finder タグ所有記録が失われ、再接続後に古い Alive タグを除去できない | オフライン中も記録を保持。内容が同じ場合は記録ファイルを再保存しない | 切断・タグ変更・再接続、個人のタグ保持、無変更時の更新日時不変を検証 |
| メニューバーのピン留めが多いと内容が縦に伸び、操作へ到達しにくい | プロジェクト領域を最大360ptでスクロール。フッターは外側に保持。少数の場合は自然な高さ | 40件と少数のレイアウトテスト。42件で同じ SwiftUI ビューをネイティブウインドウに表示して確認 |
| 不明フォルダが多いと案内が主画面を圧迫する | 4件以上の案内を独立してスクロール | 6件を表示し、末尾の復旧操作とホームの表示を確認 |
| フィルターを開いた後の一覧・タグ更新が選択肢に反映されない。未知状態で既存のプラグイン条件を解除しにくい | カタログ・メタ情報の変更で候補を更新し、選択済み条件を解除可能にする | 入力後も開始・最小・最大などのアクセシビリティ名が残ることを実画面で確認 |
| サンプル行の描画ごとに接続ボリュームを取得する | 監視済みのモデル状態からオフライン表示。読み上げ値にも未接続理由を追加 | 実画面とアクセシビリティツリーで未接続の理由を確認 |
| 拡張機能の登録情報が複数ある場合の有効判定、取得失敗・処理中の表示が不明確 | 全登録行を判定し、未登録・確認失敗・有効化中を区別。再確認と連打防止を追加 | 状態解析テスト、日英文字列テスト、日本語設定画面で再確認ボタンを確認 |

### 実画面の検証条件

- 42個の合成 `.als`、42件のピン留め、1個のサンプル、未接続ボリュームを表す参照を用意。うち1セットは400トラック。
- 別 bundle ID、専用データフォルダ、Spotlight / Finder タグ書込み / 更新確認をオフにした監査用アプリを使用。プラグイン一覧の取得は既存インストールを読取りのみで参照。
- ホームの準備状況14／42、クリック後の14件への絞り込み、フィルター解除、入力済み日付の読み上げ名、サンプルのオフライン理由、日本語設定の拡張機能再確認を確認。
- 最終ビルドでフィルターを開いたまま合成セットを保存し、候補の Live バージョンが `12.3.6` → `12.3.7` へ自動更新されることを確認。手動再スキャンは行っていない。ログでも監視通知後に1件を再解析・41件をキャッシュから再利用している。
- 6件の存在しないプロジェクトフォルダを追加した専用データで、案内だけのスクロールと6番目への到達を確認。
- メニューバーと同じ `MenuBarContent` を検証用ネイティブウインドウで表示し、42番目のピンと固定フッターを確認。OS のメニューバーポップオーバー自体は今回の UI 操作環境から取得できず、別途確認対象。
- 検証用アプリには拡張機能を同梱せず、システムの Quick Look / Widget 登録状態を変更していない。Quick Look は共通レンダラーのテストと画像検証まで。

## 残る確認と範囲

- 実ライブラリ全体の所要時間やメモリ使用率の改善率は測定していない。今回の性能改善は処理上限・キャンセル・不要なI/O削減の回帰条件で確認した。

## 変更の整理

Core の走査・履歴再生、AliveRender の描画、AliveUI の起動・連携・一覧・設定と対応する回帰テストを変更。既存のアーキテクチャ文書と日英 README も更新した。新規ファイルは監査レポートと回帰テスト3ファイルで、移植元との対応が変わる製品ファイルの新設・改名はない。
