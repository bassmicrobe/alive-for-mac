# Alive for Mac パフォーマンス・UI/UX 再監査

2026-10-05 / 対象: `main`、開始時コミット `a30dbe7`、macOS 27.0.1 / Apple Silicon / Swift 6.4。

## 結果

パフォーマンス、メモリ、キーボード操作、アクセシビリティ、フォルダ接続失敗時の復帰に
具体的な問題があり、修正した。既存のダークテーマと日本語・英語の対応を維持した。
開始時の作業ツリーはクリーン。修正は `macos/` とmacOS版の `.github/README*.md` に限定し、
上流の Windows 用ソースは変更していない。

## 問題と修正

| 優先度 | 問題・発生条件 | 修正 |
|---|---|---|
| 高 | ドライブ不通や読み取り失敗を空のフォルダと同じように扱い、前回の一覧・キャッシュを空にする | 失敗したルートと読み取れないフォルダ数を公開。ルートが読み取れない場合、前回のカタログとキャッシュを保持する |
| 高 | 400トラック、トラックを高く、32倍ズームでプレビューが約1億画素になる | 4,800万画素の上限を1倍未満の解像度でも適用。描画座標を一様に縮小して最後のトラックの欠落も防ぐ |
| 中 | サムネイルを再表示すると、メモリキャッシュの登録コストが0になり、画像が制限外に残る | ヒット後の新しいラッパーにも実際の画像コストを引き継ぐ |
| 中 | 同じサイズのサンプルが多いと、コピー参照の照合で同じ候補を繰り返し走査する | 問い合わせたサイズごとにファイル名の索引を一度だけ作る |
| 中 | 大きなサンプルのハッシュ処理が、再スキャンのキャンセル後もファイル全体を読み続ける | 1 MBごとにキャンセルを確認。途中のハッシュを採用せず、読み取りバッファもブロックごとに解放する |
| 中 | サンプルフォルダの操作時に、全ライブラリのフルパス索引をメインスレッドで作る | フォルダ検索と、そのフォルダ内のファイル名検索を分離。ファイル名の索引は24フォルダ以内に制限する |
| 中 | ホームの全ウィンドウキー監視が、ボタンやプレイヤーのキー操作を奪う | フォーカス中のタイルだけでキーを処理。矢印移動は選択・フォーカスを一緒に更新し、Return/Spaceの長押し連続実行を防ぐ |
| 中 | フォルダを読めないのに、ホームに理由も復帰操作も出ない | ホーム・セットで初回、スキャン中、正常な空結果、読み取り失敗を区別。前回の一覧を表示するときは継続的な注意とフォルダ設定への導線を出す |
| 中 | 独自エクスポートスイッチに標準のアクセシビリティ操作や明確なラベルがない | 標準Buttonを使い、切り替え属性、ラベル、オン・オフ、無効状態を公開。表示用ラベルの二重読み上げも解消する |
| 小 | Liveの記録にあるプラグインのバンドル情報を読み、後で捨てている | パスとフォーマットが既知のバンドルは、メタデータを読む前に除外する |
| 小 | 検索結果ゼロから元の一覧へ戻る操作がわかりにくい | ホーム・セット・プラグインに検索解除／フィルター解除を追加する |
| 小 | 一部の行の読み上げ操作、ミュート中の操作名、ヒートマップ右端の月名 | サンプル・プラグイン行の標準操作、ミュート解除名、読み上げヒント、月名を描画範囲内に収める処理を追加する |

大文字・小文字を区別するボリューム上で `Kicks/` と `kicks/` が共存する場合も、
元のサンプル照合結果を保つ。プラグインの過去のLiveバージョンを統合する方針や、
インストール／削除の再検出も維持している。

## 計測

| 条件 | 結果 | 解釈 |
|---|---|---|
| 合成: 同サイズ12,000ファイル、コピー参照600件 | 旧照合 2.1272秒 → 新しい使用集計全体 0.0133秒 | この条件では約160倍。実ライブラリ全体の改善率を表すものではない |
| 合成: 100,001ファイルのライブラリでフォルダと小さい別フォルダのファイルを検索 | 約0.000060秒 | 大きいライブラリ全体のパス生成を避けている。巨大な単一フォルダ内のファイル検索は、そのフォルダ内の索引作成が必要 |
| 実機: Liveの記録とバンドル情報からプラグイン検出 | 2,613件、0.95秒 | メタデータを読むテスト。プラグイン自体はロードしていない |
| 実機: フォルダだけからプラグイン検出 | 2,608件 | 記録からの検出とフォルダ検出は同一の件数とは限らない |
| ネイティブアプリ: 合成18セットの初回スキャン | 0.18秒 | 小さいローカルのテストデータ。ネットワーク／クラウド／実プロジェクトの速度ではない |
| プレビュー上限の再現条件 | 修正前 103,136,000画素、約413 MBのRGBA | 修正後は48,000,000画素以内。実測のピークRSSではない |

既存アプリのログには、フォルダ読み取り失敗と64.1秒のスキャンが残っていた。
今回のプラグイン検出は0.95秒だったが、対象・キャッシュ・時点が異なるため、
64.1秒の原因や同条件での改善率は断定していない。

## ネイティブ画面の確認

実データと設定を共有しない専用 `ALIVE_HOME`、専用bundle IDの検証アプリを使用。
Computer Useで画面とアクセシビリティ情報を確認した。

- 日本語のホーム、セット、サンプル、プラグイン、プレビュー、エクスポート画面。
- ホームで矢印キーによるタイル移動、Tabによる次のタイルへの移動、検索へのフォーカス。
- 検索に空白を含む文字を入力し、検索結果ゼロから「検索をクリア」で復帰。
- エクスポートのZIPと外部ファイルのスイッチが、1回のAX操作／マウス操作で1回だけ反転すること。
- 初回起動のフォルダ追加案内、ホーム・セットの読み取り失敗説明、フォルダ設定画面への復帰。
- 読み取り失敗時も18件の前回のプロジェクトを保持し、「最新の状態とは異なる場合があります」と表示すること。
- 最終ビルドで右端の「10月」が欠けずに表示され、スイッチ名とサンプルの読み上げヒントが重複しないこと。
- 新しく起動した検証アプリで、起動・画面遷移によるクラッシュは発生していない。

## 検証の範囲

実際のプロジェクト／サンプル全体の再スキャン、LiveでのRescue・エクスポート結果の読み込み、
実際の音声再生とメディアキー、VoiceOverの実音声、Intel／macOS 14での実行は今回の対象外。
ファイルシステムの単一の読み取りがOS側で停止している場合、その読み取り自体を途中で中断することはできない。
読み取れないルートがある間は、前回の完全なカタログを保つため、新しい部分的な更新も保留する。
