# 全体監査 2026-11-04（0.4.0）

English follows the Japanese.

## 対象と方法

- 対象: アプリ全体。特に、オリジナル 1.3.1〜1.3.3 の取り込みと、Developer ID 署名・公証の仕組み（`git diff main..port/upstream-1.3.3`）。
- 方法: 次の 3 本を並べて読み、指摘を突き合わせて重複を除きました。どれもコードを読むだけで、変更はしていません。
  - **Codex（gpt-6.1-sol）**: 正しさ、並行処理、セキュリティ（`alive://`、エクスポートのパス、データフォルダへの書き込み、Secrets の扱い）、公証の手順。
  - **swift-reviewer**: Swift の並行処理、メモリ、SwiftUI のフォーカスとキー操作、性能。
  - **silent-failure-hunter**: 失敗しても利用者が気づけない箇所（保存、スキャン、署名、リリース）。
- 修正: 2 回に分けて直しました（1 回目は Codex の 8 件、2 回目はほかの 2 本の残り）。各修正に、画面を使わずに確かめられるものはテストを 1 件ずつ付けています（`Tests/*/AuditRound1Tests.swift`、`AuditRound2Tests.swift`）。

## 1 回目（Codex の指摘 8 件、すべて修正）

| # | 重さ | 内容 | 修正 |

| 2 | 中 | 設定ファイルに一時的にアクセスできないと「無い」と判定し、あとで上書きするおそれがあった | 読み込みのエラーで判定し、「ファイルが無い」（ENOENT）以外は「読めない」として上書きしない |
| 3 | 中 | `activity.cache` が読めないと黙って作り直し、Backup に残っていない昔の作業履歴が消えた（以前からの問題） | 読めない間は書き直さず、`alive.log` に記録して次のスキャンで読み直す |

| 8 | 低 | サンプル画面で、検索欄から `↓` を押しても結果に移らなかった | 1 行目を選んでリストに移る |

## 確かめて問題がなかったもの

- `alive://open?path=` はカタログにあるセットだけを開く。通常のエクスポートのパス検査と `ditto` への引数は安全。
- ホームとセット一覧の検索ルール、`activity.cache` と `samples.cache` の末尾の追加情報（古い版との互換、途中で切れたファイル）、拍子の読み取り。
- スキャン中のフォルダ追加の待ち行列、パスの比較（フォルダ名の境界で比べる）、画面の拡大縮小の値をメインスレッド以外から読んでいないこと、プラグインのパスのキャッシュのロック。
- 署名の順序（拡張機能が先、`--deep` なし）、ハードランタイムとタイムスタンプ、2 回の公証の提出、staple と確認の順序、Secrets を `env:` だけで渡していること、一時キーチェーンの後始末。
- 拡張機能のサンドボックス（Quick Look、ウィジェットの読み取り例外）。アプリは外部のコードを読み込まないので、ハードランタイムの例外は不要（[RELEASING.md](RELEASING.md) の第 6 節）。

## 残したもの

- 6 段階の `/security-audit`（重いもの）は今回は行っていません。必要なら別に行えます。
- 画面の操作（カレンダーのキー操作、検索欄から `↓`、サンプルの空白クリック、125% の表示）は、自動テストでは確かめられないため、画面での確認に回しています。

## English

### Scope and method

The whole app, with focus on the upstream 1.3.1–1.3.3 port and the Developer ID signing / notarization pipeline (`git diff main..port/upstream-1.3.3`). Three read-only reviews ran side by side and their findings were deduplicated: **Codex (gpt-6.1-sol)** — correctness, concurrency, security (`alive://`, export paths, writes into the data folder, secret handling), notarization; **swift-reviewer** — Swift concurrency, memory, SwiftUI focus and keys, performance; **silent-failure-hunter** — failures the user cannot notice (saves, scans, signing, releases). Fixes were made in two rounds, each with one XCTest per fix that can be checked without a GUI (`Tests/*/AuditRound1Tests.swift`, `AuditRound2Tests.swift`).

### Round 1 (Codex, 8 findings, all fixed)

1. **High** — Collect All followed a symlinked "Ableton Project Info" folder and copied what it pointed to (e.g. `~/.ssh`); pre-existing. The folder itself is now checked with `lstat`; a link is not followed, an empty folder is written and the item is reported as failed.
2. **Medium** — a config file that could not be accessed was treated as missing and could be overwritten later. Only ENOENT counts as missing; any other read error is "inaccessible" and the file is not written over.
3. **Medium** — an unreadable `activity.cache` was silently rebuilt, losing history no longer in Backup folders; pre-existing. It is now kept, logged and read again on the next scan.
4. **Medium** — when `notes.cfg` and friends could not be read, every save was silently dropped while the UI looked saved. Each save now re-reads the file and applies the edit on top of it; if it is still unreadable, the Tags & Notes sheet stays open with the text and says why; settings show one toast.
5. **Medium** — a guessable temp-file name could follow an existing symlink. Temp files are now unique, created with `O_EXCL | O_NOFOLLOW`, fsynced, then renamed.
6. **Medium** — notes of a long MIDI loop vanished past beat 2,048 in the preview. Only the repetitions on screen are drawn, with the cap counted on screen.
7. **Medium** — at 125 % the main window's minimum size could exceed a small screen. Default and minimum sizes are capped to the visible frame.
8. **Low** — `↓` from the search field did nothing on Samples. It now selects the first row and focuses the list.

### Round 2 (swift-reviewer and silent-failure-hunter)

- **High** — unreadable stores (tags & notes, pins, preview pins, settings) were never announced at launch, and the check looked at other instances than the ones the app writes through. Launch now checks the stores the app uses and shows one toast; the first-run screen says settings.cfg exists but cannot be read; pin saves report their result.
- **Medium** — an empty main file replaced the good `.bak` on the next save. An empty file is no longer backed up; the case is logged.
- **Medium** — the rescue copy of a file in another encoding (e.g. Shift-JIS from the Windows app) was kept as `.bak` and lost after two saves. Rescue copies are now `.orig` (`.orig2`…); `.bak` is only the previous version; the toast names the real copy.
- **Medium** — some-but-not-all signing secrets produced an ad-hoc release with only a warning. That is now an error; only with no secrets at all does the ad-hoc fallback run.
- **Medium** — an unsigned re-run could overwrite a notarized release's assets. It now fails unless `allow_adhoc_overwrite` is set on a manual run.
- **Medium** — a sample walk that could not open a folder was stamped as complete and not retried for 24 h. It is now walked again at the next launch (an unplugged drive does not count).
- **Medium** — per-keystroke search was heavy on large libraries. Each set's searchable text is folded once and reused (rebuilt when the catalog or tags change).
- **Medium** — the inspector's Versions block was O(n²). Saves per day are counted once.
- **Low–medium** — Home dropped a Sets selection of an older folded version. It is kept when its folder's tile is visible.
- **Low** — activity-cache read failures were not logged and had no `.bak`; waveform failures were partly silent and cut-short results were cached; the export toast pointed at `alive.log` even without a log; an unreadable `nebula.cfg` was overwritten with defaults; crash leftovers of temp files stayed forever; a failed universal build fell back to one architecture during packaging; CI release builds were numbered 1 and tag runs could be cancelled; a failed playback end counted as a normal finish; the notary password was on a process command line in CI; preview cursor balance, scroller antialiasing and Retina ↔ non-Retina zoom. All fixed.

### Checked, no issue

Catalog-only `alive://open`; export path checks and `ditto` arguments; the shared search rule; the `activity.cache` / `samples.cache` tails (old-version compatibility, truncation); meter decoding; the scan queue for folders added mid-scan; path comparison on component boundaries; no off-main reads of the interface scale; the plug-in path cache lock; signing order (extensions first, no `--deep`), hardened runtime and timestamps, the two notarization submissions, stapling and verification order, secrets passed only through `env:`, temporary keychain cleanup; extension sandboxing. The app loads no third-party code, so no hardened-runtime exception is needed (section 6 of [RELEASING.md](RELEASING.md)).

### Left open

The heavy six-stage `/security-audit` was not run this time and can be run separately. On-screen behaviour (calendar keys, `↓` from search, empty-space clicks on Samples, the 125 % layout) cannot be checked by the automated tests and is left to the screen check.
