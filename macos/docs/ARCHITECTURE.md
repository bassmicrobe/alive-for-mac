# Alive for Mac — architecture (developer map)

Binding rules are in `PORTING.md`; what differs from upstream is in `../PARITY.md`. This file is the
concrete map of the finished port: modules, launch sequence, the models and how to extend them. All
UI types are internal to `AliveUI`; all models are `@MainActor @Observable`.

## Launch sequence

`AliveApp.init` → `Startup.begin()` (`Diag.start`, uncaught ObjC exception logger → `alive.log`) →
`AppModel(dataDir: AppHome.path)` loads `Settings`, sets `Localizer.shared.preference` from
`settings.lang` → `MainWindow.task` → `AppDelegate.attach(app)` + `app.start()`:
1. `RescueProbe.cleanupStale(dir:)` removes leftover probe copies listed in `probes.txt`;
   `AppHome.sweepLeftoverTemps` removes `*.tmp-<UUID>` / `*.part-<UUID>` files (and the old fixed
   `.cfg.tmp` / `.bak.part`) that a write which died left in the data folder, when over a minute old.
   Then `announceDataFileProblems()`: `announceUnreadFiles()` first (it is what reads the lazily loaded
   stores, and a non-UTF-8 file is copied aside by that read), then `announceBackedUpFiles()`: one toast
   for the data files that exist but cannot be read, one for each file copied aside (as `.orig`).
2. `CatalogModel.start()`: cache loaded off the main thread and published, then a background scan if
   there is an enabled root; it also starts `app.sets.watcher` (FSEvents, new sets appear by themselves)
   and `VolumeWatcher` (NSWorkspace mount/unmount, debounced 1.5 s -> `volumesChanged()`). That first
   scan is the only one with `fromHistory: true`: for a local root whose `scan-history.cfg` entry is
   usable it replays the FSEvents journal (`DiffScan`, `FSEventsReplay`) and re-reads only the project
   folders that changed; every other reason falls back to a full walk (`FullScanReason`, in the log),
   and any explicit rescan is a full one. Only roots on internal, non-removable volumes are replayed
   (`RootIdentity.isInternal`). Replay buffers at most 16,384 events; unreliable journals or too
   many changed regions fall back to a full walk. Its wait polls cancellation every 20 ms; a
   cancelled scan publishes no partial catalog or checkpoint. A checkpoint is committed last,
   after `index.cache` and `status.cache` were saved, together with their stamp
   (`ScanHistory.catalogStamp`; a mismatch is `.catalogMismatch`). A changed folder that cannot
   be listed (permissions, volume gone) keeps its rows (`DiffKeep`) and the root loses its checkpoint.
3. `SamplesModel.start()`: `samples.cache` shown at once, then a quiet background walk, but only when it
   is due (`SampleIndex.walkDue`: the last whole walk, stored behind the roots of `samples.cache`, is over a
   day old or a switched-on root is missing from the cache; F5, a new folder and a returning volume always
   walk). Any unreadable
   subfolder makes that root's walk incomplete, so it keeps its previous subtree; other roots can
   still update, and such a walk (`SampleIndex.buildReporting`: `incompleteRoots`) is saved with the
   walk time `.distantPast`, so the next start walks again instead of waiting a day (an offline
   volume is not incomplete: its return walks by itself). ⌘R before the tab has started sets
   `walkOnStart`, so that start walks even when the cache is fresh. A confirmed missing root is removed. Walks check cancellation between folders and
   every 256 entries within a folder; `SampleIndex.countIn` returns -1 for an incomplete walk.
4. When the catalog is ready: `catalogDidBecomeReady()` flushes Finder-opened paths
   (`app.pendingOpenPaths`, `OpenPathPlan`) and calls `UpdateModel.shared.dailyCheckIfDue` (a no-op
   unless the daily check is on).
5. `IntegrationCoordinator` (lazy on `AppModel`) follows every catalog publish: Spotlight donation, Finder
   tags, the widget snapshot (`widget/widget.json`); the menu bar extra is a `MenuBarExtra` scene in `AliveApp`
   shown while `settings.menuBar` is on.
6. `DebugLaunch.apply` (only when `ALIVE_DEBUG_*` variables are set).

## AppModel (`App/AppModel.swift`)

State: `tab: MainTab`, `searchText`, `selectedSetPath: String?`, `sheet: AppSheet?`, `toasts`,
`settings: AppSettings` (read-only outside; `AppSettings` = core `Settings`, alias because SwiftUI has a
`Settings` scene), `dataDir`, `prefs: AppPreferences`, `audio: AudioPlayback`.
Feature models (each owned by one implementer, `unowned let app`): `catalog`, `home`, `sets`, `plugins`,
`samples`, `stat`, `player`, `rescue`, `export`.

Actions: `mutateSettings { $0.x = … }` (applies, saves `settings.cfg` atomically with a `.bak` only when changed, logs
and toasts a failed write; **the only way to change settings**), `toast(_:kind:)`, `openInLive(path:)`,
`launchLive()`, `revealInFinder(path:)`, `rescan()` (the Stat window's ⌘R always rescans the catalog: `stat.isKeyWindow`), `focusResults()` (↓ in the search field: bumps `resultsFocusRequest` and calls `home.enterFromSearch()` / `sets.focusList()` / `plugins.focusList()` / `samples.focusList()`; the Samples one picks and auditions the first row, like an arrow key), `openPaths(_:)`, `present*()` (sheets),
`selectedSetPath` helpers (`openSelectedInLive`…). `shownCount` comes from the active tab's model, so a
new list must expose `shownCount`; `shownLabel` overrides the counter text (Home: "12 projects shown"; Samples: "12,923 samples ·
23.7 GB") and `activeFilterCount` feeds the badge on the Filters pill. ⇧⌘R reveals the selected set, or
the selected plugin on the Plugins tab. `mutateSettings` also re-syncs the sample roots when they change.

Tests: `AppModel(dataDir: scratch)`; never call `AppModel()` in tests (see `makeModel()` in
`AppModelTests.swift`).

## CatalogModel (`Catalog/CatalogModel.swift`)

Published: `sets: [SetEntry]` (all), `projects` (folded per folder when `settings.groupByFolder`),
`env: LiveEnvironment`, `history: Activity`, `isScanning`, `progress: CatalogProgress`
(`done,total,current,fraction?`), `lastScanStats`, `isLoaded`, `isReady` (= loaded and not scanning),
`revision` (bumped on each publish; memoize on it), `hasEnabledRoots`.
`lastScanStats.failedRoots` / `unreadableFolders` expose access failures; `missingRoots` is the subset of
failed roots whose folder does not exist (moved/deleted: `FolderScan.Result.rootMissing`, log line
`ROOT NOT FOUND`, UI `MissingRootRows` with "Choose again" = `replaceRoot(_:with:)` and "Remove" =
`removeRoot`). A root under an unmounted `/Volumes/<X>` is *offline*, never missing (`VolumeState`).
If any enabled root or one of its subfolders cannot be listed during a full walk, the previous
catalog and disk caches are retained (`retainedPreviousCatalog`); Home and Sets show recovery actions
and a persistent notice when older rows remain visible. New partial updates wait for a complete
scan, while a readable empty root still clears deleted rows.
Actions: `rescan()` (cancels and restarts; a no-op before `start()`, so root edits in tests never scan), `rescanAfterCurrent()` (for roots that were only *added*: a running scan finishes and `finishScan` starts one more scan *instead of* calling `catalogDidBecomeReady`, so Finder-opened paths and the reselect wait for the scan that has the new root), `addRoots([String])` / `addRoot(_)` (a file counts as its
folder; toasts; saves; rescans), `removeRoot(_)`, `replaceRoot(_:with:)`, `setRoot(_:enabled:)`, `settingsDidChange()`,
`volumesChanged()` (an unmount turns the sets with files there offline at once, a mount re-reads
the sets that had lost files on it and rescans a root that lives there). `statuses[path]` /
`status(for:)` give a set's `SetStatus` (`Readiness`: ready, offline, missing files, missing
plugins, unknown, unreadable; stale render), derived from `status.cache` facts, the mount table and the plugin
inventory — kept out of `index.cache`, whose layout is upstream's v11.
Core `scan` and `recheck` share a write gate, so their catalog and cache writes are serialized.
Mount notifications can update statuses while a scan runs: a scan only publishes its captured mount
table if the mount generation is still current, and status rebuilds publish only against matching
catalog and mount generations. A scan finishing after an unmount cannot restore the older table.
`index: ProjectIndex` is exposed for what the model does not wrap (`inSameFolder`, `inventory`,
`usage`…); read it, don't scan through it. Filter *then* fold: filter with `SetFilter.matchesSearch` (the one
rule of the search box for Home and Sets: every word must hit some field, width-insensitive) and then
`ProjectIndex.collapseByFolder`. The fields of a set (name, project, path, plugins, renders, tags, note) are
folded once into one text per set (`SearchHaystacks`, `app.searchHaystacks`, shared by Home and Sets and
validated by the catalog revision and `metaRevision` before each listing) and the query once
(`SearchQuery`); a keystroke is then one plain `range(of:)` per word and set.

`SetsModel.rows` = catalog narrowed by `app.searchText` (memoized), `shownCount = rows.count`.

`app.prefs.language | transparency | dailyUpdateCheck | pluginSource` are computed views onto `settings`

## Adding a sheet / menu item

Sheet: add a case to `AppSheet` (+ its `id`) and to `SheetHost`, add `app.presentXxx()` in `AppModel`,
present with `.sheet(item: $app.sheet)` (already in `MainWindow`); use `SheetFrame` for chrome.
Menu item: add a `Button` with `.keyboardShortcut` in `AppCommands`, calling an `AppModel` action;
add its title to `CommonStrings` and the shortcut to the Help sheet table.
Settings key: add the field to core `Settings` (load/serialize), expose it in `AppPreferences`. The 1.3.x keys are `uiscale` (75 / 100 / 125, applies live through `ThemeScale`) and `previewvolume` (0...1, the audition volume, written 300 ms after the last slider move and flushed on leaving the tab and on quit).

## Things that bite

- **Home grid keys belong to focused tiles** (`HomeGridKeyboard`), not a window-wide event monitor.
  Keep toolbar buttons, search, and player controls free to process their own keys.
- **Thumbnail cache costs must survive cache hits.** Both NSCaches have independent 64 MiB
  budgets; a replacement wrapper without its decoded image cost defeats eviction.
- **Quick Look fits all tracks inside a bounded bitmap.** `fitAllTracks` within at most 1100 pixels of
  height, so later tracks remain in the picture instead of being clipped; `ArrangementRender`
  downsamples logical geometry uniformly (rounding each track separately would crop the final tracks).
  The full-screen preview no longer has this limit: it keeps one viewport-sized picture
  (`ArrangementRender.makeViewImage`) and redraws it when the viewport moves. The viewport is in pixels and
  remembers the density it was measured at (`ArrangementViewport.scale`); `ensure` rescales its zoom, scroll and
  track height when the window moves to a screen of another density.
- **Looped MIDI notes are drawn for the repetitions on screen only** (`ArrangementRender.visibleRepeats`);
  the 512-repetition cap counts from the first repetition in view, so a long loop shows its notes anywhere.
- **Collect All never follows a link named "Ableton Project Info"** (`lstat` on the folder itself, not only
  on its children); a skipped one is logged and listed in `CollectResult.failed`.
- **Bar lines count the set's own bars.** Anything that draws bar lines uses `Arrangement.barBeats`
  (from the main track's time signature, 4 when absent), never a literal 4.
- **Never store a `Theme` size in a `static let` or a `let` set once.** `Theme.pad`, `rowH`, `cardR` and
  the fonts are computed over the interface scale; a stored copy only updates after a relaunch. Use
  `static var x: CGFloat { Theme.… }`. About 300 literal `.frame` / `.padding` numbers are still not
  scaled (see `PARITY.md`).
- **`HomeModel.dropHiddenSelection()` is called by the grid** (`.onChange` of the tile paths), not from
  the `rows` getter: a state write during `body` loops the structural-region pass.
- **Config files keep a `.bak`.** Every text `.cfg` goes through `AppHome.writeKeepingBackup` (a temp file
  with a unique name, created `O_EXCL | O_NOFOLLOW`, synced, then `rename`; the previous version is kept as
  `<name>.bak`; an identical save writes nothing; an empty current file is not copied over a good `.bak`;
  `activity.cache` goes through it too). `.bak` is only the writer's previous version. The copy `readConfig`
  makes of a file that is not UTF-8 (Shift-JIS from the Windows app) is `<name>.orig`, then `.orig2`…, which
  no writer touches; the launch toast names the real copy (`AppHome.BackupNotice`). A store whose file the system would not hand over
  (`ConfigRead.inaccessible`, `isUnread`) writes nothing over it: `readConfig` reads with the error in hand,
  and only ENOENT is "missing" (a folder that denies traversal is `inaccessible`, not an empty first run).
  Every save while a store is unread first reads the file again; when that works, the edit goes on top of
  what the file holds (`ProjectMeta.set` returns `StoreSave`, the Tags sheet stays open with its text and says
  why; `mutateSettings` toasts once; `HomeStore.togglePinReportingSave` and `PreviewPins.set/clear` return
  it too and `app.reportStoreSave` toasts an unread file once per session, a failed write each time).
  The launch check (`announceUnreadFiles`) reads through the instances the app writes with (`sets.meta`,
  `home`, `player.pins`), not the `.shared` ones, which can point at another data folder. `nebula.cfg` has
  the same guard (`NebulaConfig.isUnread`: `StatModel.saveNow` writes nothing over it). Changes made while the file was unread live in memory only and are
  replaced by the file's content when a read works again. Rebuildable caches have no such guard.
- **`activity.cache` has a tail.** After the moments, the `proj` mark (0x6A6F7270) and the project folder
  of each save, written only once a save has a folder (`Activity.projects(on:)`); `samples.cache` has a
  `walk` mark (0x6B6C6177) and the UTC ticks of the last walk after the roots. Both stay version 4 /
  unchanged for the 0.3.2 and upstream readers, which stop before them. An `activity.cache` that exists but
  cannot be read (`Activity.readCache` -> `isUnread`) is the only copy of the history: the scan builds from
  Backup alone, publishes that, but does not replace the file, and reads it again at the next scan.
- **Sample row lookup is local to its containing folder.** Folder operations must not build
  full paths for every sample. Case-only folder names still share the case-insensitive lookup.

- **Table cells must not read `@Environment(AppModel.self)`.** When the rows shrink, NSTableView keeps
  cells alive outside the environment and SwiftUI aborts with "No Observable object of type AppModel
  found". Pass `app` as a plain `let` (see `Sets/SetsCells.swift`).
- **Use `FileStat.of(path)` (stat(2)), not `FileManager.attributesOfItem`,** in anything that runs per file:
  the latter also reads extended attributes, which is ~28 ms per file on an SMB volume.
- **Don't raise the top bar's minimum widths.** The bar must fit in 1120 pt in Japanese with the scan
  pill showing; the search field shrinks (min 80) instead. The main and Stat windows' default and minimum
  sizes are scaled by the interface scale and capped to the screen's `visibleFrame`
  (`ScaledWindowSize`, `MainWindowSize`, `StatWindowSize`): at 125 % on a 1280-pt desktop the window is
  narrower than 1.25 x 1120.
- **Offline is not missing.** A reference or root under an unmounted `/Volumes/<X>` is offline
  (`VolumeState`); only a path that is really gone counts as missing. Do not merge the two in text or logic.
- **`index.cache` stays upstream's layout.** Mac-only per-set facts go to `status.cache`, scan positions
  to `scan-history.cfg`.
- Missing plugins are a *state* (PORTING rule 11): one aggregated mark per set, one notice per screen.

## Automated screenshots (no clicks)

Launch the built app in the background with `ALIVE_NO_ACTIVATE=1` and a scratch `ALIVE_HOME`.
**The scratch folder's `settings.cfg` must contain `spotlight=0`, `menubar=0` and `findertags=0`** before
the first launch: the defaults are Spotlight on and menu bar on, so a QA run would otherwise put its
fixture sets into the real Spotlight index and add a menu bar item (Finder tags default to off; keep
the line anyway so nothing is written into folders). The widget only reads the default data folder,
so a scratch `ALIVE_HOME` never feeds it. Under XCTest the real Spotlight index is never touched
(`XCTestConfigurationFilePath`). Then the
window numbers are written to `alive.log` (`window-number: …`), so `screencapture -l <n> -o file.png`
photographs just our window. `ALIVE_DEBUG_TAB`, `ALIVE_DEBUG_SELECT`, `ALIVE_DEBUG_PLUGIN`,
`ALIVE_DEBUG_SHEET`, `ALIVE_DEBUG_WINDOW` (`stat|player|settings`) and `ALIVE_DEBUG_SETTINGS_TAB=about`
put the app in the state you want (list at the top of `App/DebugLaunch.swift`). Pass
`-ApplePersistenceIgnoreState YES` so a previously killed run does not show the "reopen windows?"
dialog, and delete stale `NSWindow Frame …` defaults if the window opens at the wrong size.
